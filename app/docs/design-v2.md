# Design V2 · 个人成长实验室

> 愿景：从“任务处理器”升级为“个人成长实验室”——帮用户**探索想成为怎样的人**，
> 在安全的模拟中尝试，在真实行动中验证，逐渐形成自己的判断。
> 闭环：**探索 → 模拟 → 行动 → 反馈 → 理解自己 → 调整下一次尝试**。
> 学习训练只是其中一个能力，不再是全部定位。

状态标注约定：✅已确认 / 🟡候选待确认 / ⬜仅文档占位。

---

## 0. 最终定稿（用户确认 · 2026-10-03 第三轮）

- **主打模块**：情境剧场 B（关系 + 健康情境），核心创新 = **关键节点分支重演**。
- **证明不只好玩**：个人实验室 E（模拟 → 现实小实验 → 反馈 → 成长记录）。
- **闭环必做**：探索 → 模拟 → 重演 → 实验 → 反馈 → 成长记录。
- **降级**：学习工坊 D 保留但非主打（“只有学习工坊太单一，不可能拿奖”）。
- **暂缓**：多视角圆桌 C（未获优先；单模型多角色方案留作后续）。
- **关系健康场景定位**：作为情境剧场 B 的**场景内容**，不是独立诊断模块。

**关系健康场景的安全边界（作主打，必须守住）**：
- 模拟 ≠ 建议 ≠ 预测真人：角色反应只是练习材料。
- 健康场景只做“沟通/表达”类（表达关切、和家人沟通压力、拒绝不健康社交），
  **不做医疗诊断 / 治疗 / 减肥 / 营养处方**。
- 红旗词（自伤 / 严重身体不适）→ 立即停止模拟，输出转介话术。
- 关系场景不生成“对方一定如何反应”的预测，只练“不同说法带来不同结果”。

## A. 探索空间 🟡

**用户需求**：不知道想做什么，只有“最近很迷茫”这类模糊感受。

| 维度 | 内容 |
|---|---|
| 交互流程 | 抛具体经历/情境 → 用户选“想尝试/不确定/不喜欢/暂时放下” → 组织成探索地图 → 生成一个低成本可撤回小实验 |
| 输入 | 模糊自述、情境卡片选择、对候选方向的表态 |
| 输出 | 探索地图（含“互相矛盾愿望可共存”）、小实验建议 |
| 持久化 | `explorations` 表：方向、用户表态、假设、时间 |
| 调用角色 | 探索教练（单一角色，不诊断） |
| 权限边界 | 所有推断是可编辑假设，非人格定论；不生成“你适合当 X” |
| 异常行为 | 用户拒绝表态 → 不强行归类；矛盾愿望 → 保留不合并 |
| 验收 | 用户获得“一个新尝试”而非“一个标签”；假设可编辑 |

---

## B. 情境剧场 🟡

**用户需求**：知道道理，但面试/表达分歧/团队协作等情境不会用。

| 维度 | 内容 |
|---|---|
| 交互流程 | 进入场景（角色+背景+目标+限制）→ 按回应推进剧情 → 可暂停/提示/回放关键节点 → 分支重演“换一种说法”→ 结束展示行为依据与其他路径 |
| 输入 | 场景选择、用户回应文本 |
| 输出 | 剧情推进、关键节点回放、分支对比、行为依据 |
| 持久化 | `scenarios` 表 + `scene_runs`（分支时间线、用户回应、重演记录） |
| 调用角色 | 模拟角色（多角色，各自独立，**不声称预测真人**） |
| 权限边界 | 模拟反应只是模拟；不生成“真人一定会如此反应”的结论 |
| 异常行为 | 用户要求提示 → 给提示不泄露答案；重演 → 保留两条分支不覆盖 |
| 验收 | 能重演关键选择并比较路径；能导出“行为依据与其他可能路径” |

---

## C. 多视角圆桌 🟡

**用户需求**：复杂选择时，单个 AI 答案太确定，遗漏不同利益与假设。

| 维度 | 内容 |
|---|---|
| 交互流程 | 按问题选视角（探索机会/约束资源/找反例）→ 各角色独立分析 → 展示真正分歧 → 用户改条件看结论变化 → 记录用户选择及理由 |
| 输入 | 决策问题、条件参数、视角选择 |
| 输出 | 观点对比卡、假设地图、各观点“依据/假设/不知道” |
| 持久化 | `discussions` 表：视角、观点、假设、用户最终选择+理由 |
| 调用角色 | 多视角（同模型多次调用，角色化 prompt；**共享同一模型偏见，不以数量冒充可信度**） |
| 权限边界 | 不“多数 Agent 同意”裁定正确答案；不合成圆滑答案 |
| 异常行为 | 视角间无分歧 → 如实说“无实质分歧”，不制造冲突 |
| 验收 | 用户能发现原来忽略的条件/风险；分歧真实展示 |

## D. 学习工坊 ✅

**用户需求**：三个教学模式（限时学习破局 / 目标路线教练 / 理解漏洞检测）。

| 维度 | 内容 |
|---|---|
| 交互流程 | 选模式 → 限时破局=围绕成果紧凑实践；路线教练=按进展调整；漏洞检测=追问理由/换情境/测迁移 |
| 输入 | 目标/成果、进度回报、反馈方式选择 |
| 输出 | 任务拆解（W+预估）、路线调整、漏洞检测追问 |
| 持久化 | 复用 `goals` + `daily_entries`；新增 `learning_events`（被提示完成 vs 独立完成） |
| 调用角色 | 学习教练（单一角色）；运行时按需用“温和提示/直接解释/挑战追问”三种反馈 |
| 权限边界 | 不固定“错两次才解释”绑所有用户；区分“被提示完成”与“独立完成” |
| 异常行为 | 连续中断 → 非惩罚恢复（不回滚清零、不羞辱） |
| 验收 | 学习结果能进入情境剧场检验迁移；反馈方式用户可选 |

## E. 个人实验室 🟡

**用户需求**：聊完很有启发，却没有实际变化。

| 维度 | 内容 |
|---|---|
| 交互流程 | 讨论 → 转成小实验（验证什么/做什么/记录什么/何时回看）→ 记录作品/感受/意外 → 复盘“预期 vs 实际”→ 允许推翻原计划 |
| 输入 | 讨论结论、实验设计字段、回访反馈 |
| 输出 | 实验卡、复盘对比、是否保留/推翻计划 |
| 持久化 | `experiments` 表：假设、动作、记录、回看日期、结果 |
| 调用角色 | 实验教练（单一角色） |
| 权限边界 | 不完成也记录原因，**不用羞辱/连续打卡惩罚推动** |
| 异常行为 | 用户放弃实验 → 记录原因，不惩罚 |
| 验收 | 讨论能产出“可执行动作”；复盘比较预期 vs 实际而非只问“完成了吗” |

## F. 成长地图 🟡

**用户需求**：学习、模拟、现实经历割裂，看不到变化。

| 维度 | 内容 |
|---|---|
| 交互流程 | 汇总：尝试过的领域/场景、作品与关键经历、用户确认的偏好、待验证假设、同类场景前后差异 |
| 输入 | 各模块沉淀的数据 |
| 输出 | 成长档案（可查看/纠正/删除）；不生成虚假分数 |
| 持久化 | `memory_entries` 表（每条带出处+可编辑/删除标记）；复用 selfagent `assets.md`/`rules.md` 结构 |
| 调用角色 | 无独立角色，聚合层 |
| 权限边界 | 用户可查看、纠正、删除系统记忆；**不生成“心理成熟度 87 分”** |
| 异常行为 | 错误记忆被纠正 → 停止影响后续行为 |
| 验收 | 错误记忆可被修正并停止影响；前后差异有出处可追溯 |

## G. 研究与内容工作台 ✅（后台，不全部暴露给用户）

| 维度 | 内容 |
|---|---|
| 交互流程 | 运维侧管理：证据卡片、场景/教学任务/提示策略、视觉资产许可、内容版本审核、用户反馈与失败案例库 |
| 输入 | 论文/资料原文、场景脚本、视觉资产 |
| 输出 | 研究卡片、内容版本、许可清单 |
| 持久化 | `knowledge_cards` / `scenarios` / `assets` / `content_versions` / `failure_cases` |
| 调用角色 | 心理学研究 Agent（人工核验后放行） |
| 权限边界 | 理论不是装饰：一篇论文≠功能有效；未核验标“待核验”不进用户建议 |
| 异常行为 | 无来源 → 留空不编造 |
| 验收 | 研究卡片结构完整：来源→支持什么→不支持什么→对应功能假设→如何验证→风险与适用限制 |

## 第一条闭环（首版主路径）

```
用户提出真实困惑
 → 探索可尝试的方向（A）
 → 进入一个模拟场景（B）
 → 重演一个关键选择（B 分支重演）
 → 制定现实小实验（E）
 → 提交反馈（E 回访）
 → 更新可编辑的成长记录（F）
```
**完整模块图保留，但首版只把这条闭环跑通。** 心理学研究与视觉探索并行，不阻塞基础流程。

## UI：两层导航（“空间”而非聊天窗口合集）

- **按意图进入**：我想探索 / 我想练习 / 我面临选择 / 我想复盘
- **按空间展开**：探索地图、情境剧场、学习工坊、实验室、成长档案

聊天只是交互手段，主要内容是：场景卡片+分支时间线、观点对比+假设地图、实验记录+作品展示、可追溯反馈卡片。

视觉候选（不替你决定审美）：温暖实验室 / 沉浸式剧场 / 克制个人工作台——每个方向须说明“怎样支持使用”，不只漂亮。

## 安全与隐私边界（全模块硬规则）

- 不诊断、不治疗、不做人格评分、不诱导依赖
- 模拟结果不声称预测真人；多 Agent 共识不当作事实
- 心理学资料必须可核验来源+适用限制
- 用户可查看/纠正/删除个人记录；敏感自述默认隐藏，展示需同意
- 模拟数据、占位素材、测试响应明确标记
