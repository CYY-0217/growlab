## 2. 启动方式与技术栈

- 后端：Python **FastAPI** + **SQLite**（单文件 `learner_agent.db`）+ **DeepSeek API**（OpenAI 兼容接口，`model=deepseek-chat`）。
- 前端：单文件 `static/index.html`，原生 JS 单页应用——无框架、无构建步骤、无 CDN，图片/SVG 全部离线本地资源。
- 启动：`./.venv/bin/uvicorn main:app --port 8300`（Python 3.12 venv）。
- 结论：**不是只有前端**，有后端 + 数据库 + 真实模型调用。

## 3. 产品内部是否有「多个 Agent」

**这是本说明最重要的一点，需要区分两层：**

### （A）开发时：有
编码过程中用了多个子 Agent 做探索、设计、检索。这是**开发协作**，与产品运行无关。

### （B）运行时：没有真正的多 Agent 协同
产品**不是**多个自治 Agent 互相协作。技术真相是：

- **单个后端进程，调用单一 LLM（DeepSeek `deepseek-chat`）**。
- 通过 **9 个不同的 system prompt 模板**在不同场景「扮演」不同能力：
  `scene_character` / `scene_compare` / `explore` / `experiment_plan` / `experiment_review` / `task_breakdown` / `daily_adjustment` / `weekly_report` / `idea_deconstruction`。
- **没有 Agent 之间的通信、没有多 Agent 共识/投票机制**。
- 文档里「多 Agent 共识不当作事实」指的是：情境剧场里「角色」与「评估」由同一模型完成，是**一个模型的角色扮演 + 打分**，不是独立智能体互相验证。

**一句话**：「Agent」是产品话术；技术上 = 单模型 + 多提示词分派。审查时请按这个事实评估。

## 4. 一条核心用户流程（自律打卡）

> 页面 → 接口 → 数据存哪 → 是否用模拟数据

1. 打开首页默认「自律」→ `GET /api/users/{uid}/discipline` → 返回目标清单、今日 checkins、近 30 天历史、统计。读 SQLite `goals`、`daily_entries` 表。
2. 点一个目标打卡 → `POST /api/users/{uid}/discipline/check {goal_id, checked}` → 写 `daily_entries.checkins`（JSON 字段）；若是**新**打卡，同时 `pet_reward` 给宠物加经验（写 `pets.exp`、`pet_events`）。
3. 专注计时 → `POST /api/users/{uid}/discipline/focus {minutes}` → 累加 `daily_entries.focus_min`。
4. 今日复盘 → `POST /api/users/{uid}/discipline/note {note}` → 写 `daily_entries.note`。

- 数据：全在 SQLite。**此流程无模拟数据**，都是真实 DB 写入。
- 说明：演示用的 4 个学习者账号（化名：小韵/阿澈/周舟/小闪）+ 10 条使用记录，是**手动导入的种子数据**（来自用户提供的真实使用记录），不是系统自动生成。

### 另一条（有真实模型调用的）流程：情境剧场

1. 选场景 → `GET /api/scenarios`（读 `scenarios` 表）。
2. 开始 → `POST /api/scenes/{slug}/start` → 建 `scene_runs`。
3. 每说一句 → `POST /api/scenes/run/{rid}/advance` → **真实调用 DeepSeek**（`scene_character`）→ 追加时间线 → 返回角色回复 + 评估。
4. 重演 → `POST /replay` 建新分支；对比 → `POST /compare` **真实调用**（`scene_compare`）。
5. 每次模型输入/输出都落 `agent_outputs` 表，可追溯。
