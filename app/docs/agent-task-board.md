# Agent 任务板（并行协作分工）

> Claude Code 负责核心代码与集成；其他 Agent 分别负责需求恢复、UX、视觉素材、
> 心理学研究、场景内容、独立评测、隐私审查。
> **若本会话无对应子 Agent 能力，则输出可独立执行的任务书，不假装已启动。**

每个任务含：背景 / 目标 / 可读资料 / 可改路径 / 交付格式 / 验收要求。

---

## T0 · Claude Code（实现与集成负责人）—— 本会话

- **背景**：Design V2 已产出，等待用户确认关键取舍后再实现。
- **目标**：架构、状态管理、接口、运行系统、测试与集成；保护未提交修改。
- **可读**：`docs/*`、`database.py`、`main.py`、`agent_engine.py`、`prompts.py`、`../selfagent/*`
- **可改**：`personal/learner-agent/**`
- **交付**：跑通第一条闭环（探索→模拟→重演→实验→反馈→成长记录），含测试。
- **验收**：闭环可运行；非静态页/空接口；测试覆盖见 acceptance-tests.md。

---

## T1 · 需求恢复 Agent

- **背景**：原始脑暴分散，需建立覆盖表防止静默删除。
- **目标**：从已有文档恢复原始脑暴，建立功能来源与覆盖表。
- **可读**：`../selfagent/CLAUDE.md`、`../selfagent/memory/*`、`../selfagent/reports/*`、`../50-Day-Discipline/index.html`、`docs/requirements-coverage.md`
- **可改**：`docs/requirements-coverage.md`（只读其他文件）
- **交付**：覆盖表补全（原始功能/来源/模块/现状/缺失/待确认）。
- **验收**：每条需求有来源；找不到的标“无记录”，不编造。

---

## T2 · UX Agent

- **背景**：两层导航“按意图/按空间”，需要入口与场景流程设计。
- **目标**：入口设计、场景流程、异常状态、交互原型。
- **可读**：`docs/design-v2.md`、`static/index.html`
- **可改**：`docs/`（交付原型到 `docs/ux/`，不直接改 `static/` 未确认）
- **交付**：两条主路径的交互稿（探索→实验、情境→重演），含异常态（空态/失败/中断恢复）。
- **验收**：每条路径含输入→输出→异常→恢复；不依赖模型记忆管理流程状态。

---

## T3 · 视觉与素材 Agent

- **背景**：UI 要做成“空间”，先出概念稿不替你定审美。
- **目标**：风格候选（温暖实验室/沉浸式剧场/克制个人工作台）、组件视觉、资产与许可清单。
- **可读**：`docs/design-v2.md` UI 节、`static/index.html`
- **可改**：`docs/visual/`（概念稿）
- **交付**：≥2 个方向概念稿，各附“怎样支持使用”说明 + 资产许可清单。
- **验收**：每个方向说明使用价值，非只看漂亮；占位素材明确标注。

---

## T4 · 心理学研究 Agent

- **背景**：知识卡须有可核验来源，理论不是装饰。
- **目标**：产出证据卡片（来源→支持什么→不支持什么→功能假设→如何验证→风险与适用限制）。
- **可读**：`docs/design-v2.md` G 节；可联网检索（有 skill 时）
- **可改**：`docs/research/`（研究卡片）
- **交付**：首批 2-4 张卡（含 WHO《Doing What Matters in Times of Stress》原文核验）。
- **验收**：每卡来源可核验、标注适用限制；未核验标“待核验”；不做诊断/治疗承诺。

---

## T5 · 场景与内容 Agent

- **背景**：情境剧场需要脚本与分支。
- **目标**：情境脚本、角色限制、学习任务与分支条件。
- **可读**：`docs/design-v2.md` B 节
- **可改**：`docs/scenes/`
- **交付**：1-2 个场景脚本（角色/背景/目标/限制/≥2 分支/关键节点）。
- **验收**：角色反应标注“模拟非预测”；分支可重演；含“换一种说法”对照。

---

## T6 · 独立评测 Agent

- **背景**：避免“自己写自己夸”。
- **目标**：新上下文测试、失败案例、复现报告。
- **可读**：`docs/acceptance-tests.md`、运行中的系统
- **可改**：`docs/evaluation/`（失败案例、复现报告）
- **交付**：按验收清单逐项出通过/失败 + 失败复现步骤。
- **验收**：覆盖暂停恢复、分支重演、调用失败、记忆纠正、删除、越权访问。

---

## T7 · 隐私与安全 Agent

- **背景**：记忆权限、数据删除、敏感场景与风险审查。
- **目标**：审查敏感自述收集、记忆可编辑/删除、越权访问、健康场景边界。
- **可读**：`docs/interfaces.md` 权限节、`database.py`
- **可改**：`docs/security/`（审查报告）
- **交付**：风险清单 + 每项对应控制措施（软删/同意/最小化/转介）。
- **验收**：无诊断/治疗承诺；敏感数据默认隐藏；删除可落地；越权访问被拦截。

---

## 协作规则

1. 公共接口、数据库结构、依赖变更由 T0 统一协调，其他 Agent 不直接改 schema。
2. 检查 Git 状态，保护未提交修改；确认后使用独立分支/工作目录隔离。
3. 运行时按需调用教练/模拟角色/评审角色，不每次拉全体开会，用户不承担等待。
4. 无子 Agent 能力时：输出任务书（本文件），不假装已启动或已并行完成。
